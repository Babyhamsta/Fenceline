## Implemented findings

| # | Defect | Change |
|---|---|---|
| 1 | Concurrent cold pin hydration loses a detected host. | Share hydration and serialize persisted snapshots. |
| 2 | Concurrent cold log hydration loses events; clearing can race with reads/writes. | Share hydration, invalidate stale reads, serialize writes and clearing. |
| 3 | Existing pins still blanket-block newly excluded no-pin hosts. | Consult current exclusions on lookup and await initial policy hydration. |
| 4 | Manual sync saves the no-pin baseline without activating it. | Refresh effective exclusions before responding. |
| 5 | Separate IndexedDB writes can leave mixed artifact generations. | Commit and read related tail/model keys in single transactions; activate memory after commit. |
| 6 | Failed DNR installation is treated as up-to-date on retry. | Require both artifact and successful-sync versions; retry incomplete installation without the bandwidth throttle. |
| 7 | A text-only model update retains stale fusion. | Explicitly replace persisted and active fusion with null. |
| 8 | DNR placement/category changes do not change list identity. | Include category names and DNR chunk manifest in the version. |
| 9 | No-pin/model-only changes are skipped by publication. | Separate publication identity includes independent metadata, excluding generation time. |
| 10 | Clean CI checkout omits the model from published artifacts. | Fall back to committed extension model; trigger publication on model changes. |
| 11 | Intercept/threshold/metadata-only model exports keep the old version. | Hash canonical inference metadata, weights, and optional fusion in both exporters. |
| 12 | Unicode separators inside valid JSONL strings crash metrics loading. | Split records on LF only. |
| 13 | Empty-body pages and metadata/structure-only changes are suppressed. | Deduplicate the complete payload with an unset initial signature; observe relevant document changes. |
| 14 | Continuous DOM mutations postpone scanning indefinitely. | Preserve the pending deadline; retain cooldown, busy protection, and message cap. |
| 15 | Changing blockSubframes leaves installed list rules unchanged. | Refresh resource types on affected installed rules. |

Synchronization and policy operations also share an execution queue. Reusing
hydration removes duplicate storage reads; scanner attempts respect cooldown even
when content is unchanged. These are bounded cost improvements, not benchmarked
throughput claims.
